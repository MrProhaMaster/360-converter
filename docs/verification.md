Для версии 1.1 добавлена проверка нажатия «Вырезать 4 направления»: пять синтетических панорам дают 20 JPEG. Проверены индивидуальные углы и размеры, сохранение ICC, отсутствие EXIF, неизменность исходников и настроек, выбор файлов/папки и отмена этих диалогов. Во время обработки обе кнопки экспорта заблокированы; после завершения, ошибки или отмены снова доступны. Проверка кнопки «Отменить» выявила привязку к устаревшему сигналу отмены — обработчик исправлен. При 1000×720 все четыре кнопки помещаются без перекрытий.

В первоначальном изолированном запуске Tk не смог прочитать системный Tcl и GUI-тест был пропущен. Повтор в обычном профиле Windows с отдельной временной папкой завершился **без пропусков**. Это ограничение среды проверки, а не требование запускать приложение от администратора.

## Встроенный FFmpeg в 1.4

Windows-пакет содержит `bin/ffmpeg.exe`; программа находит его по расположению EXE, независимо от текущей папки, PATH и `IMAGEIO_FFMPEG_EXE`. Проверены поиск в переносимой папке и `_internal`, приоритет встроенной копии, явное переопределение для CLI, ошибка при неполной распаковке и сохранение внешнего FFmpeg для запуска исходников. GUI автоматически запускает экспорт четырёх видов без ручного выбора FFmpeg.

Сборка проверяет закреплённую версию, SHA-256 и фильтр `v360`, добавляет лицензии и сведения о происхождении. Затем готовый `Pano360.exe --cli` выполняет экспорт 1/4/6 видов из другой папки с кириллицей и пробелами; PATH ограничен Windows System32, переменные Python/Tcl/ImageIO удалены из окружения дочернего процесса. Все 11 JPEG созданы с ожидаемыми размерами, ICC совпадает побайтово, EXIF отсутствует, исходник не изменён. Проверка запускается автоматически перед публикацией артефакта GitHub Actions. Это проверка автономности приложения на текущем ПК, не замена испытания на чистой виртуальной машине или рабочем компьютере с корпоративными ограничениями.

Проверка GitHub выявила ошибку вывода Unicode-отчёта при системной кодировке cp1252: после успешного экспорта процесс останавливался на печати кириллического имени. Вывод CLI переведён в UTF-8. Добавлены регрессионный запуск с `PYTHONIOENCODING=cp1252` и запуск без stdout/stderr, как у оконного EXE. CI также закреплён на Python 3.14.0 и проверенном файле зависимостей.

## Шаровой контроллер в 1.3

Поля yaw/pitch/roll удалены из окна; вместо них используется шар с цветными кольцами X/Y/Z, свободным вращением и выбором оси. Проверены матрицы последовательных поворотов, обратное преобразование в старый формат углов у полюсов и на границе ±180°, устойчивость свободного вращения на противоположных точках шара. Ориентация совпадает с текущим направлением предпросмотра и сохраняется после загрузки пресета, закрепления за фото и фактического экспорта шести JPEG. GUI-тест проверяет отсутствие трёх полей, наличие FOV, работу мыши/клавиатуры/колёсика и уточнение кадра после отпускания. Контроллер помещается в минимальное окно 1000×720. Итоговый локальный прогон: **55 passed, без пропусков**.

## Плавность предпросмотра в 1.2

Старый обработчик ждал паузу 280 мс после каждого движения и отменял предыдущий процесс FFmpeg. Теперь панорама кешируется в памяти, работает один поток предпросмотра с последними параметрами, а готовые промежуточные кадры показываются и при продолжающемся движении. Размер промежуточного кадра адаптируется к времени расчёта. После отпускания мыши строится уточнённый кадр.

Добавлены независимые сравнения с FFmpeg для совместных yaw/pitch/roll, режимов 1/4/6, зенита, надира и границы ±180°. На синтетической панораме с непрерывным кодированием направления в RGB средняя разница с экспортом менее 2 уровней на канал (это проверка геометрии, не требование побайтового совпадения). Проверены ограничение кеша, инвалидирование при замене файла, некорректный ICC, непрерывное перетаскивание при медленном расчёте, итоговый ракурс после отпускания и отбрасывание старого кадра при переключении фотографии.

Замер в локальном тесте Tk-окна 1240×850: **117 обновлений за 3,00 с, около 39 обновлений/с**; 95-й процентиль интервала между показами — 29,5 мс. Использована синтетическая панорама, адаптивное разрешение включено, окно на время замера скрыто. Это результат конкретного тестового ПК, не обещание одинаковой частоты на другом оборудовании. Качество JPEG-экспорта не менялось.

Из-за непостоянного доступа тестовой среды к системным Tcl-файлам окончательный локальный прогон использовал их копию в рабочей папке и переменные `TCL_LIBRARY`/`TK_LIBRARY` только для процесса тестов: **44 passed, без пропусков**. Системная установка Python не изменялась. В переносимом EXE Tcl/Tk поставляется внутри папки приложения.

## Границы проверки

Не проверены чистая виртуальная машина без установленного Python, Windows 11/ARM, экранный диктор, все варианты DPI/масштабирования, сетевые/FAT-диски, реальные сбои питания и панорамы на предельных размерах. Tk имеет ограниченную поддержку Windows UI Automation; управление с клавиатуры доступно, но полная совместимость с экранным диктором не заявляется. EXE не подписан сертификатом и не снабжён установщиком.

Исходный ZIP прототипа недоступен, поэтому нет проверки его исходного кода, импорта старой схемы `user_photos.json` и совпадения пикселей с прежними 20 результатами. Новые результаты используют настройки по умолчанию, а не неизвестные персональные углы старого пресета.

GitHub Actions успешно выполнил Windows-тесты, сборку и публикацию артефакта для коммита `67a5b61`: https://github.com/MrProhaMaster/pano360-converter/actions/runs/45612640400. Для последующих изменений проверяйте соответствующий запуск на вкладке Actions.

Собранный EXE отдельно проверен через его окно: загрузка синтетической панорамы с кириллическим именем, выбор FFmpeg, предпросмотр с ICC и успешный экспорт JPEG. При минимальном размере окна 1000×720 автоматический GUI-тест подтверждает, что элементы экспорта не перекрыты нижней панелью.
