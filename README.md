# Pano360 — панорама в кадр

Локальное Windows-приложение для преобразования готовых эквиректангулярных JPEG 360° (строго 2:1) в обычные перспективные JPEG. Русский GUI, предпросмотр, управление мышью, yaw/pitch/roll, горизонтальный FOV, пакетный экспорт, пресеты и CLI. После установки обработка работает без сети. Фото никуда не отправляются.

## Быстрый запуск Windows

1. Установите Python 3.11–3.14 с Tk и FFmpeg с фильтром `v360` из доверенного источника. Ссылки на Windows-сборки: https://ffmpeg.org/download.html#build-windows.
2. В папке проекта выполните:

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -e "."
.venv\Scripts\python launch.py
```

Для готовой переносимой сборки распакуйте **всю папку** Pano360 и откройте `Pano360.exe`. Python отдельно не нужен. FFmpeg поставляется отдельно: выберите `ffmpeg.exe` в приложении, поместите рядом с EXE либо добавьте в PATH. Готовая сборка не скачивает компоненты самостоятельно.

## Работа в окне

1. Добавьте фотографии или папку (без рекурсивного обхода). Выберите панораму в списке.
2. Укажите FFmpeg. Предпросмотр обновляется после паузы в редактировании; окно не блокируется.
3. Задайте поворот, наклон, крен и FOV. Можно перетаскивать предпросмотр. Поля дают альтернативу мыши; `Ctrl+O` открывает выбор файлов.
4. Выберите 1, 4 либо 6 видов, размер и качество JPEG. В меню над предпросмотром можно посмотреть отдельное направление. Для режима 1 показывается только основной вид, для 4 верх/низ показывают передний вид.
5. По умолчанию текущие настройки применяются ко всем фотографиям. «Закрепить за фото» сохраняет отдельные настройки для выбранного файла **в рамках сеанса** (отметка `*`). При выборе закреплённого фото его настройки загружаются в поля. Чтобы изменить их для экспорта, закрепите заново. Остальные фото используют текущие поля.
6. Укажите папку экспорта и нажмите «Экспортировать все панорамы». Каждый запуск создаёт новую подпапку `pano360-дата-время-...`. «Открыть результат» открывает её в Проводнике.

После отмены уже готовые JPEG сохраняются. Текущий процесс FFmpeg завершается, незаконченный кадр не публикуется. Ошибки отдельных файлов не прерывают весь пакет; итог — в локальном `report.json`.

## Геометрия и размеры

- 1 вид — прямолинейная проекция выбранного направления. По умолчанию 1024×768, горизонтальный угол 90°.
- 4 вида — направления 0°, 90°, 180°, −90° относительно скорректированной сферы. При FOV < 90° остаются горизонтальные пропуски. Зенит и надир не покрываются.
- 6 видов — четыре стороны плюс верх и низ: квадратные грани по 90°. Поля высоты и FOV игнорируются; сторона равна ширине. Эти грани покрывают всю сферу.
- Положительный yaw смотрит вправо, положительный pitch — вверх. Порядок вращения FFmpeg: `ypr`. Для 4/6 сначала поворачивается вся сфера, затем извлекаются виды, чтобы крен/наклон были общими для всех граней. Это два этапа интерполяции; возможна небольшая дополнительная мягкость.
- FOV — 20–140°, размеры 64–8192, максимум 32 Мп на кадр. Вход — до 80 Мп. Увеличение размера не добавляет деталей.

## Цвет, метаданные и безопасность файлов

ICC переносится в JPEG побайтово. EXIF/GPS, XMP/GPano и IPTC не копируются. JFIF и технические JPEG-заголовки остаются. Для экрана ICC преобразуется в sRGB, если профиль поддерживается Pillow; экспорт сохраняет оригинальный профиль. Это не калибровка монитора.

Исходники не изменяются. Запись поверх исходника или уже существующего кадра запрещена. JPEG сначала записывается во временный файл в папке назначения, затем публикуется операцией без замены существующего файла. Дубликаты имён разделяются порядковым номером. Даже два одновременных запуска получают разные папки. При аварийном отключении питания возможен оставшийся `.tmp`; это не готовый JPEG.

FFmpeg запускается списком аргументов, без командной оболочки. Пресеты содержат только числа и версию схемы; пути и команды из них не исполняются. Фото, EXE, временные данные и секреты исключены из Git. Программа не содержит телеметрии, обновлятора и сетевых запросов. Выбирайте доверенный `ffmpeg.exe`.

## Пресеты и CLI

В `presets/` есть три общих пресета. «Сохранить пресет» сохраняет текущие параметры; «Открыть пресет» загружает их. Индивидуальные назначения файлов не входят в пресет — это намеренно переносимый документ без личных имён.

```powershell
.venv\Scripts\python -m pano360.cli "C:\Photos\pano.jpg" --output "C:\Converted" --views 4 --yaw 12 --roll -2 --ffmpeg "C:\Tools\ffmpeg.exe"
.venv\Scripts\python -m pano360.cli "C:\Photos" --output "C:\Converted" --preset presets\cube-six.json --ffmpeg "C:\Tools\ffmpeg.exe"
```

CLI: код возврата 0 — успех, 1 — ошибки отдельных файлов, 2 — неверные параметры/ошибка подготовки. Явные CLI-параметры переопределяют пресет.

## Тесты и сборка EXE

```powershell
.venv\Scripts\python -m pip install -e ".[dev]"
.venv\Scripts\python -m pytest -q
pwsh -File scripts\build_windows.ps1 -Python .venv\Scripts\python.exe
```

Результат: `dist/Pano360/Pano360.exe` и необходимые файлы в той же папке. Сборка выполняется в Windows; кросс-сборка Windows EXE из Linux не предусмотрена. FFmpeg не включается в распространяемую папку. Для интеграционных тестов используется бинарник из dev-зависимости `imageio-ffmpeg` либо `PANO360_TEST_FFMPEG`. CI в GitHub Actions выполняет тесты и публикует переносимую папку как артефакт; автоматического Release нет.

## Происхождение и ограничения

Реализовано по описанию предыдущего прототипа `local_360_converter.zip`: FFmpeg `v360`, JPEG 2:1, ручные углы, выборочный перенос ICC и безопасный экспорт. **Сам архив оказался недоступен по ссылке старого чата. Его код и `user_photos.json` не были получены и не включены.** Совместимость с неизвестной схемой старых пресетов и пиксельное совпадение с теми 20 кадрами не заявляются. Здесь новый версионированный формат пресетов, PNG-промежуточный кадр и JPEG-кодировщик Pillow.

Не поддерживаются RAW, dual-fisheye, несшитые кадры, частичные панорамы, CMYK/серые JPEG, видео и автоматическое выравнивание горизонта. EXIF Orientation, отличный от 1, отклоняется, чтобы не ошибиться с геометрией. На больших панорамах возможен заметный расход памяти; предпросмотр ограничивает выходной размер, но FFmpeg всё равно декодирует полный источник. Тайм-аут одного кадра — 180 секунд. Пакет обрабатывается последовательно.

Подробности фактической проверки: [docs/verification.md](docs/verification.md). Сведения о зависимостях: [THIRD_PARTY.md](THIRD_PARTY.md).
