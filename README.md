# Pano360 — панорама в кадр

Локальное Windows-приложение для преобразования готовых эквиректангулярных JPEG 360° (строго 2:1) в обычные перспективные JPEG. Русский GUI, предпросмотр, шаровой контроллер, пакетное сохранение кадров, пресеты и CLI. Обработка работает без сети. Фото никуда не отправляются.

## Быстрый запуск Windows

1. Для запуска исходников установите Python 3.11–3.14 с Tk. **Начиная с версии 1.5.1 FFmpeg устанавливается вместе с обычными зависимостями приложения** через `imageio-ffmpeg`; отдельно скачивать FFmpeg, настраивать PATH или выбирать путь не нужно. Интернет требуется только для первоначальной установки зависимостей.
2. В папке проекта выполните:

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -e "."
.venv\Scripts\python launch.py
```

Если исходники уже были установлены, обновите их и в том же окружении Python выполните:

```powershell
python -m pip install --upgrade .
python launch.py
```

Запускайте команды из папки проекта. Если вы используете `.venv`, вместо `python` укажите `.venv\Scripts\python.exe`. Просто обновить `.py`-файлы недостаточно: старая установка могла не содержать новую зависимость с FFmpeg. Проверка: `python -c "from pano360.core import find_ffmpeg; print(find_ffmpeg())"` — путь должен вести к установленному `imageio_ffmpeg/binaries/` (либо к вашей явно указанной копии).

Для готовой переносимой сборки **1.4 и новее** распакуйте **всю папку** Pano360 и откройте `Pano360.exe`. **Python, библиотеки и FFmpeg уже включены.** Установка, права администратора, интернет и изменение PATH для работы не требуются. Сохраните папки `bin` и `_internal` рядом с EXE; копировать только `Pano360.exe` нельзя. Начиная с версии 1.5 строка FFmpeg скрыта, встроенная копия используется автоматически. Готовая сборка не скачивает компоненты самостоятельно. Команды установки через Python выше относятся только к исходникам.

## Работа в окне

1. Добавьте фотографии или папку (без рекурсивного обхода). Выберите панораму в списке.
2. Предпросмотр появляется сразу после загрузки панорамы. Экспорт автоматически использует FFmpeg из переносимой сборки либо из установленных зависимостей Python; выбирать его вручную не нужно.
3. Вращайте ракурс шаровым контроллером в правом верхнем углу предпросмотра. Перетаскивание самой фотографии также работает; `Ctrl+O` открывает выбор файлов.
4. Поля углов, FOV, размера, качества и числа видов скрыты. По умолчанию используется один кадр 1024×768, FOV 90°, качество JPEG 95; кнопка «Вырезать 4 направления» создаёт четыре кадра. Для другого набора параметров откройте JSON-пресет, например `presets/cube-six.json` для шести граней. В меню над предпросмотром можно посмотреть отдельное направление. Для режима 1 показывается только основной вид, для 4 верх/низ показывают передний вид.
5. По умолчанию текущие настройки применяются ко всем фотографиям. «Закрепить за фото» сохраняет отдельные настройки для выбранного файла **в рамках сеанса** (отметка `*`). При выборе закреплённого фото его настройки восстанавливаются. Чтобы изменить их для сохранения кадров, закрепите заново. Остальные фото используют текущую ориентацию и параметры пресета.
6. Нажмите **«Вырезать 4 направления»**, чтобы сразу получить по четыре JPEG из **каждой панорамы в списке**: вперёд, вправо, назад и влево (шаг 90°). Например, пять панорам дадут 20 кадров. Если список пуст, откроется выбор фотографий; если папка экспорта не указана — выбор папки. Отмена любого диалога отменяет запуск.
7. Кнопка «Сохранить кадры» сохраняет текущий ракурс либо набор 1/4/6 видов из загруженного пресета. Каждый запуск создаёт новую подпапку `pano360-дата-время-...`. «Открыть результат» открывает её в Проводнике.

Быстрая кнопка использует текущие yaw/pitch/roll, FOV, размер и качество, а для закреплённых фото — их индивидуальные параметры. Только число видов на этот запуск становится равным четырём, даже если у фото сохранён режим 1 или 6. Пресет и закреплённые настройки не изменяются. По умолчанию кадры имеют размер 1024×768 и FOV 90°; при меньшем FOV между направлениями будут пропуски. ICC сохраняется. Это повторяет схему «один основной ракурс + три других», но не восстанавливает неизвестные персональные углы из старого чата.

После отмены уже готовые JPEG сохраняются. Текущий процесс FFmpeg завершается, незаконченный кадр не публикуется. Ошибки отдельных файлов не прерывают весь пакет; итог — в локальном `report.json`.

## Шаровой контроллер X/Y/Z

- В режиме «Своб.» тяните любую часть шара, включая цветные кольца и подписи осей: вращение остаётся свободным, X/Y/Z автоматически не выбираются. Этот режим включён при запуске.
- Чтобы явно ограничить вращение, нажмите отдельную кнопку **X**, **Y**, **Z** под шаром, затем тяните мышь: вправо/вверх — положительный поворот, влево/вниз — отрицательный. Вернуться к свободному вращению можно кнопкой «Своб.». Оси фиксированы относительно панорамы: **X — вправо, Y — вперёд, Z — вверх** в исходном положении. Цвета: красный, зелёный, синий. Кольца и подвижные подписи только отражают текущую ориентацию.
- Колёсико над шаром, кнопки «+»/«−» под предпросмотром и стрелки при фокусе на шаре поворачивают на 2°. **Shift** уменьшает шаг до 0,25° для клавиш/колесика и замедляет перетаскивание. В режиме «Своб.» «+»/«−» и колёсико вращают вокруг Z, стрелки вверх/вниз — вокруг X.
- Клавиши **X/Y/Z** выбирают ось, **F** — свободный режим, **Home** сбрасывает только ориентацию, **Esc** отменяет текущий жест. Tab переводит фокус на следующий элемент.

Контроллер соответствует текущему направлению предпросмотра, включая виды справа, сверху и снизу в режимах 4/6. Ориентация сохраняется в пресетах, индивидуальных настройках и экспорте. Существующие JSON-пресеты с yaw/pitch/roll продолжают работать; три угла остаются внутренним форматом данных и доступны в CLI.

## Плавное вращение предпросмотра

Удерживайте левую кнопку мыши и двигайте кадр. Панорама один раз загружается в память; следующие ракурсы рассчитываются без повторного чтения JPEG и запуска FFmpeg. Во время движения кадр обновляется непрерывно, без ожидания остановки мыши. Очередь устаревших положений не накапливается.

Для быстрого отклика используются кадры до 480×320; их детализация автоматически подстраивается под скорость компьютера. После отпускания мыши размер уточняется до 720×460. Размер изображения в окне остаётся прежним. В памяти хранится уменьшенная копия последней панорамы до 2048×1024 с применённым ICC. Предпросмотр использует билинейную интерполяцию, экспорт — прежний FFmpeg с кубической интерполяцией и полным исходным разрешением. Скорость зависит от компьютера; фиксированная частота кадров не гарантируется. Все библиотеки предпросмотра включены в готовый EXE.

## Геометрия и размеры

- 1 вид — прямолинейная проекция выбранного направления. По умолчанию 1024×768, горизонтальный угол 90°.
- 4 вида — направления 0°, 90°, 180°, −90° относительно скорректированной сферы. При FOV < 90° остаются горизонтальные пропуски. Зенит и надир не покрываются.
- 6 видов — четыре стороны плюс верх и низ: квадратные грани по 90°. Параметры высоты и FOV игнорируются; сторона равна ширине. Эти грани покрывают всю сферу.
- Положительный yaw смотрит вправо, положительный pitch — вверх. Порядок вращения FFmpeg: `ypr`. Для 4/6 сначала поворачивается вся сфера, затем извлекаются виды, чтобы крен/наклон были общими для всех граней. Это два этапа интерполяции; возможна небольшая дополнительная мягкость.
- FOV — 20–140°, размеры 64–8192, максимум 32 Мп на кадр. Вход — до 80 Мп. Увеличение размера не добавляет деталей.

## Цвет, метаданные и безопасность файлов

ICC переносится в JPEG побайтово. EXIF/GPS, XMP/GPano и IPTC не копируются. JFIF и технические JPEG-заголовки остаются. Для экрана ICC преобразуется в sRGB, если профиль поддерживается Pillow; экспорт сохраняет оригинальный профиль. Это не калибровка монитора.

Исходники не изменяются. Запись поверх исходника или уже существующего кадра запрещена. JPEG сначала записывается во временный файл в папке назначения, затем публикуется операцией без замены существующего файла. Дубликаты имён разделяются порядковым номером. Даже два одновременных запуска получают разные папки. При аварийном отключении питания возможен оставшийся `.tmp`; это не готовый JPEG.

FFmpeg запускается списком аргументов, без командной оболочки. Пресеты содержат только числа и версию схемы; пути и команды из них не исполняются. Фото, EXE, временные данные и секреты исключены из Git. Программа не содержит телеметрии, обновлятора и сетевых запросов. Переносимая сборка предпочитает свой `bin/ffmpeg.exe` программе из PATH и не ищет его в текущей рабочей папке. Исходники автоматически используют `imageio-ffmpeg` после проверки явно заданного пути и файлов рядом с приложением. `--ffmpeg` в CLI и стандартная переменная `IMAGEIO_FFMPEG_EXE` позволяют сознательно переопределить копию для исходников.

## Пресеты и CLI

В `presets/` есть три общих пресета. «Сохранить пресет» сохраняет текущие параметры; «Открыть пресет» загружает их. Индивидуальные назначения файлов не входят в пресет — это намеренно переносимый документ без личных имён.

```powershell
.venv\Scripts\python -m pano360.cli "C:\Photos\pano.jpg" --output "C:\Converted" --views 4 --yaw 12 --roll -2
.venv\Scripts\python -m pano360.cli "C:\Photos" --output "C:\Converted" --preset presets\cube-six.json
```

CLI: код возврата 0 — успех, 1 — ошибки отдельных файлов, 2 — неверные параметры/ошибка подготовки. Явные CLI-параметры переопределяют пресет.

Переносимый EXE также поддерживает `Pano360.exe --cli <вход> --output <папка> --views 4` без установленного Python и без параметра `--ffmpeg`. У оконного EXE нет консоли: результат записывается в `report.json` папки экспорта. Для ожидания завершения и проверки кода возврата в PowerShell используйте `Start-Process -Wait -PassThru`.

## Тесты и сборка EXE

```powershell
.venv\Scripts\python -m pip install -r requirements-dev.lock.txt
.venv\Scripts\python -m pip install --no-deps -e .
.venv\Scripts\python -m pytest -q
pwsh -File scripts\build_windows.ps1 -Python .venv\Scripts\python.exe
```

Результат: `dist/Pano360/Pano360.exe`, `bin/ffmpeg.exe`, `_internal/` и документация. Сборка выполняется в Windows x64; кросс-сборка Windows EXE из Linux не предусмотрена. `scripts/bundle_ffmpeg.py` берёт FFmpeg 9.0.2 из закреплённого wheel `imageio-ffmpeg==0.8.1`, сверяет SHA-256 и наличие `v360`, затем копирует бинарник без изменений и лицензионные сведения. Переменные `IMAGEIO_FFMPEG_EXE` и PATH не влияют на выбор включаемого файла. При несовпадении версии или контрольной суммы сборка завершается ошибкой.

В конце сборки `scripts/check_windows_bundle.py` запускает **готовый EXE** с PATH только из Windows System32, из другой папки с кириллицей и пробелами. Проверяются экспорт 1/4/6 видов, размеры, ICC, отсутствие EXIF и сохранность источника. Это также обязательный шаг GitHub Actions перед публикацией артефакта. CI использует Python 3.14.0 и `requirements-dev.lock.txt`, чтобы состав сборки совпадал с проверенной локальной средой. Для обычных интеграционных тестов можно задать `PANO360_TEST_FFMPEG`. Автоматического Release нет.

Отдельная проверка CI на **Python 3.13.3** создаёт чистое окружение, устанавливает только `pip install .` без dev-зависимостей и выполняет `scripts/check_source_install.py`. Скрипт проверяет найденный FFmpeg внутри установленного пакета и экспорт 1/4/6 видов с PATH только из Windows System32. Установка тестируемого приложения не подменяется импортом исходников из рабочей папки.

## Происхождение и ограничения

Реализовано по описанию предыдущего прототипа `local_360_converter.zip`: FFmpeg `v360`, JPEG 2:1, ручные углы, выборочный перенос ICC и безопасный экспорт. **Сам архив оказался недоступен по ссылке старого чата. Его код и `user_photos.json` не были получены и не включены.** Совместимость с неизвестной схемой старых пресетов и пиксельное совпадение с теми 20 кадрами не заявляются. Здесь новый версионированный формат пресетов, PNG-промежуточный кадр и JPEG-кодировщик Pillow.

Не поддерживаются RAW, dual-fisheye, несшитые кадры, частичные панорамы, CMYK/серые JPEG, видео и автоматическое выравнивание горизонта. EXIF Orientation, отличный от 1, отклоняется, чтобы не ошибиться с геометрией. На больших панорамах возможен заметный расход памяти при первоначальной загрузке; последующие повороты предпросмотра используют уменьшенную копию. Экспорт декодирует полный источник. Тайм-аут одного экспортируемого кадра — 180 секунд. Пакет обрабатывается последовательно.

Подробности фактической проверки: [docs/verification.md](docs/verification.md). Сведения о зависимостях: [THIRD_PARTY.md](THIRD_PARTY.md).
